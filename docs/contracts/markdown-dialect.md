# Markdown 方言

## 基础方言与扩展

解析器以固定版本 pulldown-cmark 识别 CommonMark/GFM 语法，由 Moino 构造无损 CST、标记区间、可控扩展、节点身份及块级增量复用。复用经过规范样例检验的语法识别，避免维护第二套基础语法；库的默认扩展不自动成为产品方言。GPUI Kit 的 TextView 解析器不解释文档，只接收 Moino 投影的块树；源码模式也使用同一 CST 提供高亮。

- 块级解析遵循 CommonMark 0.31.2：段落、ATX 与 Setext 标题、围栏与缩进代码块、块引用、有序与无序列表、主题分隔线、HTML 块、链接引用定义。
- 启用 GFM 0.29-gfm 扩展：表格、删除线、任务列表、自动链接（不含 www 前缀的裸 URL）。
- 启用 Moino 扩展：数学 `$…$`（行内）与 `$$…$$`（块）、`==高亮==`、`~下标~`、`^上标^`、`[toc]` 文内目录、提示块 `> [!type]`、以 `---` 开始 `---` 或 `...` 结束的 YAML 文档元数据、脚注 `[^id]`。
- 未启用的扩展按普通文本保留其标记，不产生错误。

## 块解析优先级

- 块级识别顺序：文档元数据（仅文档开头）→ 围栏代码块 → 提示块 → 块引用 → 列表 → 数学块 `$$` → 表格 → ATX 标题 → Setext 标题 → 主题分隔线 → HTML 块 → 链接引用定义 → 缩进代码块 → 段落。
- 数学块 `$$` 与围栏代码块独占一行起止；行内数学不允许跨行，未闭合的 `$` 按普通文本处理。
- 表格块要求表头行、分隔行与至少一行数据行；分隔行单元格只含 `-`、`: ` 与空格。

## CST 与标记区间

- 解析产出无损 CST：每个节点携带"原始区间"（含语法标记）与"内容区间"（去标记后正文），两者以标量偏移表达；所有原始区间按文档顺序拼接等于源文本。
- 每个内联语法节点（强调、删除线、高亮、上下标、行内数学、行内代码、链接、图片、脚注引用）单独暴露前标记、后标记与内容三个区间。
- 解析器对任意输入不 panic，返回完整 CST；未知或未闭合标记按普通文本保留，不产生错误节点。

## 增量解析与节点身份

- 编辑后的重解析以块为粒度：受影响的块区间（编辑区间所在块 + 因边界变化可能受影响的相邻块）被重解析，未受影响块的子树整体复用且 `NodeId` 不变。
- 事务传入实际编辑区间，不能仅凭相同文本的最长公共前后缀推断节点身份。围栏与容器边界传播时扩大窗口，直到后缀稳定；引用的全局解析上下文无法局部独立解释时保守重建语义，仍按实际编辑映射保留未修改节点身份。可能全量失效的工作走[离线准备与前台发布](../architecture.md#运行时模型)。
- `NodeId` 由"父 ID + 块内序号 + 局部指纹"派生；块内容不变时 ID 稳定，块被拆分时两个新块取新 ID。
- 增量解析结果与对同一文本的全量解析结果语义等价（树形与区间一致），`NodeId` 可不同。

## 锚点与引用

- 标题生成锚点：正文小写化、去除标点、空白折叠为 `-`；同文档内重复锚点追加 `-1`、`-2` 序号。
- 链接引用标签规范化：折叠连续空白、不区分大小写；查找以规范化形式进行。

## 序列化保真

- 导出为 Markdown 时逐字节还原权威文本（无损）；重排或规范化是独立操作，不属于序列化路径。

解析与重解析在事务提交后同步完成（块级增量成本有界）；全文解析放在后台任务（见[任务调度（预留）](../planned.md#jobs)）。扩展开关属于有效设置，设置变化触发对应范围重解析。

内部不一致触发[文档保护](document-model.md#文档不变量)。
