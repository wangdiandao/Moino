# 撤销与重做

## 撤销单元

事务是最小撤销单位。撤销回退一个事务或合并组的全部编辑并恢复原选择，重做重新应用；两者不产生新历史项。撤销后提交新事务会清空重做栈。

事务可携带 `HistoryGroup`。同一文档、同一活动块、相同输入类型和方向的连续输入，在距本组起点不足 3000 ms 时合并；窗口不随每次输入滑动。替换操作不合并。使用受控时钟，前台时窗口有效，挂起恢复后重新计时；普通计时边界见[运行时](../architecture.md#运行时模型)。

## 历史边界

Enter、块候选正式化、格式命令、粘贴、拖放与替换等结构操作独立成组，不与相邻输入合并。光标或选择变化、显式保存、切换文档、命令、撤销重做和文件事件切断合并。IME 提交按文本输入类型登记，取消不产生历史；是否与相邻输入合并遵循同一块、类型、方向与时间窗口，而不是仅因收到 compositionend 就强制拆组。

文档历史位置有独立于单调修订号的稳定身份，撤销和重做恢复该身份；编辑会话以此保存候选块状态。只改变候选与正式状态的转换也可形成历史单元，不改写 Markdown，不改变脏状态。

即时预览与源码模式共享历史栈。代码、数学和 HTML 的专用表面先维护局部历史，退出时收敛为文档中的可撤销单元。恢复点不进入历史，崩溃恢复后历史栈为空。

## 历史预算

默认最多 1000 个撤销单元，超限静默丢弃最旧单元。单个单元的文本增量不设硬上限，仍受文档大小和[资源预算](../planned.md#quality)约束。撤销无法映射时返回 `history.cannot_undo`，保留当前状态。

## 文件操作历史

侧栏移动、删除和重命名单独维护文件操作历史，每次操作为一个撤销单位，不进入文档栈。
