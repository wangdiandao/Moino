# 基础验证

M0 验证[路线图](../roadmap.md#里程碑)的工程与技术边界。原型使用固定样本和独立入口，不承诺正式产品的编辑、保存或恢复能力；失败须返回诊断，不能以静态占位图代替真实引擎输出。

## 自动检查

`cargo xtask layers` 读取 Cargo metadata，校验[内部依赖允许表](../architecture.md#分层与-crate)、L0 不依赖 GPUI、testkit 只供开发使用、成员继承工作区依赖和 lint。`cargo xtask docs` 检查仓库 Markdown 的本地文件、章节和入口可达性；外部链接不在离线门禁中请求。

`cargo xtask vectors` 解析全部正式 YAML，校验字段、唯一名称、归属章节和场景锚点，保留文本空格与尾换行。它只验证数据，不执行 M1 的产品断言。`cargo xtask trace` 将向量与规格、场景的关联写入 `target/trace.json`，执行覆盖与待实现状态必须分开，报告不提交仓库。

`moino_testkit` 提供向量加载和受控时钟。时钟只能显式前进，溢出拒绝且不改变当前时间；验证期限前一刻、恰好到期、取消和旧身份拒绝，不真实等待。

## 技术原型

| 入口 | 判定 |
|---|---|
| `cargo run -p moino --example m0` | 原生装饰窗口，正文经 `editor_host` 排版；键盘与鼠标输入更新宿主文本，UTF-16 输入范围与叶几何转换一致 |
| 同一窗口的专用表面 | 静态与 Kit `Editor` 切换前后比较位置、尺寸和滚动锚点，遵循[几何容差](../design/layout-geometry.md#编辑表面)，不能只比较容器的设定值 |
| 同一窗口的数学和图表 | 固定 TeX 经 RaTeX、固定 Mermaid 经 merman 生成实际矢量并由 GPUI 显示，错误保留输入 |
| `cargo run -p moino_export --example m0` | 生成含中日韩、长段落、跨页表格与标题的 PDF，检查孤行寡行、重复表头、书签、文字可搜索、字体嵌入，记录编译耗时、页数与字节数 |
| PDF 页面预览 | hayro 解码上项 PDF，输出页面位图；检查文字、矢量和图像，不以 PDF 文件头代替页面断言 |
| IPC 集成测试 | 两个真实进程完成本地端点监听、第二实例转发与确认；畸形和超限消息拒绝，监听者退出后端点可重用 |

## 真实系统检查

Windows 实测拼音、日文、韩文、Emoji 的组合、提交、取消与候选框位置；受控输入处理器测试只证明输入契约。原生装饰下用 Alt / F10 打开菜单、方向键选择、Escape 逐层返回，并比较菜单前后正文几何。

在 Windows UI Automation、macOS VoiceOver、Linux Orca 检查正文文本、选择、可编辑状态和焦点；可访问名称存在不能替代文本范围、插入点与读屏操作。三平台 CI 分别编译并运行自动检查，真实系统结果与限制记录在对应 Issue，不写成规格完成度。
